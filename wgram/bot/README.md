# Бот профилей WGram для BotHost

Публичная группа не нужна. Бот принимает фото в личных сообщениях;
профили и значки выдаёт подключённым клиентам через HTTPS API.
Обычный Telegram не отображает баннеры и награды WGram в профилях.
Метаданные доступны всем авторизованным пользователям сервиса; это не
секретное хранилище от технически подготовленного пользователя.

1. В @BotFather создай бота. Токен добавь только в переменную `BOT_TOKEN` в BotHost.
2. Загрузи содержимое этой папки. Главный файл: `bot.py`, Python 3.11+.
   Включи «Использовать собственный Dockerfile». Для ZIP-загрузки включи
   «Загрузка бота из архива» в профиле BotHost. По документации BotHost
   загрузка архивов доступна на Базовом/Pro и пока ограничена тестовой нодой:
   [инструкция загрузки](https://bothost.ru/docs/upload-bot-archive).
   При использовании приватного Git-репозитория сначала настрой доступ BotHost к нему.
3. Выдели постоянное хранилище для `WGRAM_DATA_DIR` (например `/app/data`).
   В нём SQLite с профилями, баннерами, значками и хешами временных сессий.
   Без постоянного диска пересоздание контейнера потеряет данные.
4. Укажи `PORT=3000`, подключи HTTPS-домен к этому порту. API без HTTPS в моде не принимается.
5. В WGram открой подключение сервиса и введи HTTPS-адрес. Нажми подключить,
   затем отправь стартовую команду боту. Пароли, SMS-коды и API hash боту не нужны.
6. Публикуй оформление из WGram или отправь фото боту в личку.
   Значки выдаёт только пользователь 8226881959.

Проверка отправителя выполняется по Telegram `from.id`, только в личной переписке;
пересланные команды не принимаются. Одноразовая привязка действует 5 минут,
сессия клиента — 30 дней; токены хранятся в БД только как SHA-256.
Чужой ID в JSON не позволяет менять чужой профиль. Сервис не имеет доступа
к чьей-либо сессии Telegram, личным чатам и кодам входа.

Фото, отправленное боту, доступно Telegram и оператору хостинга.
Публикация добровольная. Удаление оформления из приложения удаляет запись
и баннер из сервиса; копии уже отправленных сообщений боту нужно удалить в Telegram отдельно.
База и её резервные копии содержат пользовательские данные — доступ к диску должен быть закрыт.

Документация BotHost: [переменные](https://bothost.ru/docs/environment-variables),
[домен и порт](https://bothost.ru/docs/domains-and-ports),
[база в /app/data](https://bothost.ru/docs/database-storage).

Запуск тестов: `python -m unittest discover -s tests -v`.

## Общий каталог кастомок (0.4)

Все пользователи могут отправлять работы в личку боту. Привязка WGram нужна
для просмотра и применения в приложении; для отправки работы боту достаточно
обычного аккаунта Telegram. Случайное фото без команды по-прежнему сохраняется
только как личный баннер. Ничего не публикуется в каталог автоматически.

- `/customs` — инструкция.
- Фото с подписью `/custom Название` — баннер в общий каталог.
- `/submit Название` — снимок ранее опубликованного профиля (баннер,
  эмодзи-статус, цвет, локальный Premium). Награды не копируются.
- Кастомный эмодзи отдельным сообщением — добавить его без поиска ID.
  Также поддерживается `/emoji ID Название`.
- Ссылка `https://t.me/addemoji/Имя` или `https://t.me/addstickers/Имя` — набор.
  Бот проверяет существование и тип через `getStickerSet`.
- `/catalog` — последние одобренные работы, `/mine` — свои и их статусы.
- `/remove ID` — удалить свою работу. Чужую может удалить только администратор.

Администратор `8226881959`: `/pending` — очередь,
`/approve ID` — одобрить, `/reject ID` — отклонить.
Ссылки на работы имеют вид `https://t.me/ИМЯ_БОТА?start=custom_ID`.
Неодобренную работу по ссылке видят только автор и администратор.

В WGram: Настройки WGram → Каталог кастомок. Есть просмотр баннера,
применение оформления, открытие наборов, отправка собственного оформления
и удаление своих работ. «Мои работы» показывает также очередь и отклонённые
варианты. Для каталога все пользователи должны указать один и тот же URL сервиса.

Чтобы одобренные работы дополнительно отправлялись в группу или канал,
добавь бота туда и задай в BotHost **`WGRAM_CATALOG_CHAT_ID`**:
числовой ID, например `-1001234567890`, или `@username` публичного канала.
В канале боту нужно право публикации. Без переменной работает каталог внутри
WGram и бота. Очередь доставки хранится в SQLite; ошибка Telegram не мешает
боту принимать команды. После потери ответа возможен повтор поста.
Удаление работы из каталога не удаляет прежние посты и сохранённые людьми копии.

Работы сохраняются отдельными снимками: изменение своего профиля не меняет
чужие применённые варианты и уже отправленные работы. Авторство — Telegram ID.
Содержимое доступно авторизованным пользователям сервиса, поэтому не публикуй
то, что не хочешь распространять. До 30 работ на автора, до 1000 на сервис;
одинаковые повторные отправки не создают дубликат. БД обновляется автоматически
без удаления прежних профилей, баннеров, наград и сессий.

API (везде требуется Bearer-сессия клиента):

- `GET /v1/customs[?mine=1&before=ID&kind=emoji]` — страницы по 20 записей,
  поле `next` — курсор следующей страницы или `0`.
- `POST /v1/customs` — `title`, `kind` (`profile`, `banner`, `emoji`),
  для `emoji` также `emoji`; автор берётся только из сессии.
- `GET /v1/customs/ID` — метаданные и payload;
  `GET /v1/customs/ID/banner` — JPEG, если есть.
- `POST /v1/customs/ID/delete` — автор или администратор.

Готовый архив `WGramBot-0.4.zip` содержит обновлённый сервис и тесты.
Сам архив не запускает хостинг и не создаёт Telegram-группу.
